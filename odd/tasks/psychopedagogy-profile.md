### Integration contract
Types live in src/modules/psychopedagogy/lib/profile-contract.ts (backend owns file). Section key: learning | followups | interventions | instruments. StudentOption: id, firstName, lastName, group.name.
GET /api/teacher/students/{id}/psychopedagogy/profile -> { profile: { learningStyleAndTemperament: string, observations: {id,entryDate,title,body}[], accompaniments: {id,entryDate,kind:INDIVIDUAL|FAMILY,title,body}[], interventions: {id,entryDate,title,observationAnalysis,strategyFeedback,workPlan,implementation,evaluationResults}[], instruments: {id,entryDate,name,body}[] } }. Dates JSON ISO strings. Empty profile yields empty string/arrays without inserting on GET.
POST same path -> {ok:true}, section-discriminated payload: {section:learning,description}; {section:accompaniment,date,kind,title,body}; {section:intervention,date,title,observationAnalysis,strategyFeedback,workPlan,implementation,evaluationResults}; {section:instrument,date,name,body}. Learning upsert; others append with author from authenticated specialist active TeacherProfile. Text limits10000, titles/name160; real YYYY-MM-DD validation. Observations continue existing GET/POST base psychopedagogy endpoint (date,title,body); profile GET includes existing entries.
Backend exports GET and POST in server/psychopedagogy-profile.handlers.ts; parent route reexports. UI exports PsychopedagogyProfile({student,readOnly,initialSection?}) in components/psychopedagogy-profile.tsx (four accordion sections in detail); PsychopedagogyProfileSection({student,readOnly,section}) in same file used in table section modal, owns fetch/form lifecycle. New shared reusable section editor never fetches classroom-report data. Parent guards entire profile block to specialist with dashboard.access and Superadmin. Preserve established table filter/name links/status placeholder, rebalance columns for four-icon group; no visible Actions header.
