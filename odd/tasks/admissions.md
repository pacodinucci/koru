## Integration contract

Backend owns `src/modules/admissions/initial-questionnaire.ts` (browser-safe ordered definitions and types), `src/modules/admissions/admissions.schema.ts`, `src/modules/admissions/server/**`, `src/modules/contacts/server/**`, `src/modules/contacts/contacts.domain.ts` and `src/modules/contacts/contacts.handler.ts`, `src/app/api/admissions/route.ts`, `src/app/api/dashboard/contacts/**`, additive Prisma changes and backend tests. Frontend owns public `/admisiones/cuestionario-inicial`, dashboard `/dashboard/contactos` and `/dashboard/contactos/[source]/[id]`, its views, sidebar and admissions CTA; it consumes backend HTTP APIs, never changes authorization.

Public `POST /api/admissions`: `{ questionnaireVersion: "initial-v1", idempotencyKey: UUID, answers: {...}, website?: "" }`. Return `{ success: true }` only after persistence; failure `{ success: false, error: string }` and appropriate HTTP status. Same key + same normalized content returns success; same key + different content returns 409 with no mutation. Keep key in component memory across retries, regenerate only for a new successful submission. Honeypot `website` and bounded JSON body (64 KiB) are first-party abuse controls, not a claim of distributed rate limiting.

General answer keys in order: `childName`, `birthDate`, `age`, `guardianNames`, `phone`, `email`, `city`. All strings except integer `age`; birthDate ISO calendar date not in future; age 0–25; names max 200 characters, city 120, phone 40, email 254. Narrative string keys in section order (max 4,000 characters each, optional): `childDescription`, `enjoys`, `interests`, `relationships`, `importantTraits`; `previousEducation`, `schoolExperience`, `likedEducation`, `desiredChanges`; `discovery`, `projectAttraction`, `childExpectations`, `familyExpectations`; `dailyRhythm`, `supportNeeds`, `currentNeeds`. These are technical validation limits, not new product questions. Export `QUESTIONNAIRE_VERSION`, `QUESTIONNAIRE_SECTIONS` ({ title, description?, questions: { key, label, type, required, maxLength? }[] }), `QUESTIONNAIRE_INTRO` (string array), and `QUESTIONNAIRE_PRIVACY` from browser-safe definition. Public form can assemble answers generically using question type (`text`, `date`, `number`, `tel`, `email`, `textarea`).

Admin `GET /api/dashboard/contacts?q=&source=&status=&page=1`: `{ items: ContactRow[], total, page, pageSize:20 }`. Source tokens `contact` and `admission`; status tokens `NEW`, `READ`, `REPLIED`. Row `{ source, id, name, email, phone: string|null, status, receivedAt: ISO string }`. Deterministic global receivedAt descending then source then id. Search admission guardian/child name or email; contact name or email. `GET /api/dashboard/contacts/[source]/[id]`: `{ item: ContactDetail }`, detail row plus `message?:string`, `answers?:Record<string,string|number>`, `questionnaireVersion?:string`. `PATCH` same detail route accepts strictly `{status}` and returns `{success:true}`. Every read checks contacts.view server-side; status writes require both contacts.view and contacts.manage. SUPERADMIN inherits all catalog capabilities; explicit permissions for other roles remain authoritative. Invalid filters yield 400, forbidden 403, missing 404, safe server failure 500. Components may render version initial-v1 via definition; unknown stored versions display an explicit safe unsupported-version state rather than relabeling answers. Dashboard back link retains q/source/status/page.
