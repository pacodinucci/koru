## Interface contract
- Admin page: /dashboard/teachers/[teacherId]/follow-up-agreements, SUPERADMIN only; teacher-profile lookup before page body after guard.
- Recipient page: /dashboard/mis-acuerdos-seguimiento, TEACHER/ADMIN_TEACHER only. This must not replace /dashboard/acuerdos-seguimiento (agreements those teachers author about students).
- Repository: src/modules/follow-up-agreements/server/teacher-follow-up-agreements.repository.ts exports listTeacherFollowUpAgreements(teacherId) (SUPERADMIN only) and listOwnTeacherFollowUpAgreements() (TEACHER/ADMIN_TEACHER only, published and addressed to authenticated profile). Return serializable rows: id, teacherId, title, body, status ('DRAFT'|'PUBLISHED'), createdAt (ISO string), publishedAt (ISO|null), acceptedAt (ISO|null), acceptedByName (string|null), authorName (string), attachmentName (string|null), hasAttachment (boolean). Never serialize Cloudinary ids or URLs.
- Multipart POST /api/teacher-follow-up-agreements fields teacherId,title,body,file(optional) creates DRAFT. PATCH /api/teacher-follow-up-agreements/[id] multipart title,body,file(optional; absent preserves attachment) only DRAFT. DELETE /api/teacher-follow-up-agreements/[id] matches existing admin workflow.
- POST /api/teacher-follow-up-agreements/[id]/publish only SUPERADMIN, draft to published. POST /api/teacher-follow-up-agreements/[id]/consent only addressed actual TEACHER/ADMIN_TEACHER user and PUBLISHED; record first actor/time and preserve on repeated consent. GET /api/teacher-follow-up-agreements/[id]/attachment SUPERADMIN or own published recipient only, authenticated byte proxy; never return signed storage URL.
- Mutation responses {ok:true} on success; {error:string} appropriate status on failure. Author/recipient are server-derived/validated, never accept creator/consenter from client. Validate all inputs and attachment signatures/types/size using existing agreement patterns, preserve existing APIs.
- UI surface names: teacher-follow-up-agreements-client.tsx and teacher-follow-up-agreement-form.tsx under existing components directory. Admin view dashboard-teacher-follow-up-agreements-view.tsx under teachers/views. Backend and UI must report contract deviations rather than silently diverge.
